# Question Paper Submission Module — Feature Architecture & Plan

## 1. Executive Summary & Objective

This document outlines the architectural design and workflow for adding a **Question Paper Submission Module** for teachers in the **PS Cadet College Exam Application**.

The module provides teachers with a streamlined platform to submit examination papers—either by writing them directly inside the application or uploading external documents (PDF, Word, Images)—while giving administrators and academic coordinators an audit trail and review system.

---

## 2. User Experience & Workflow

The module will be accessible as a dedicated tab in the navigation menu (**"📝 Question Paper Submission"**).

### Step 1: Metadata Selection
Before entering content or uploading files, teachers select target examination details:
* **Grade / Class:** e.g., Grade 9, 10, 11, 12
* **Subject:** Filtered dynamically based on selected grade
* **Examination Term:** Linked to `Exam_ID` (e.g., `EXAM_MID_TERM_2026`, `EXAM_ANNUAL_2026`)
* **Teacher Name / ID:** Selected or auto-filled from session state

### Step 2: Submission Mode Selection
Teachers can choose between two submission options via a tab toggle:

#### **Option A: ✍️ In-App Direct Writing**
* **Input Interface:** Multi-line text area or rich-text editor (`st.text_area` / `streamlit-quill`).
* **Formatting Controls:** Support for header sections (Section A: MCQs, Section B: Short Questions, Section C: Long/Descriptive Questions), marks distribution, and time limit.
* **Live Preview:** Instant rendering of formatted text.
* **Auto PDF Export:** Generates a standardized, printable PDF version of the typed exam paper.

#### **Option B: 📁 External File Upload**
* **Input Interface:** File drag-and-drop uploader (`st.file_uploader`).
* **Supported Extensions:** `.pdf`, `.docx`, `.doc`, `.png`, `.jpg`, `.jpeg`.
* **Validation & Preview:** File size limit checks (e.g., max 15MB) and image/PDF thumbnail previews.

---

## 3. Data Architecture & Storage Strategy

A dual-tier storage strategy handles text metadata and binary file storage cleanly.

### Tier 1: Master Database Log (`Question_Papers_Log` Sheet)
A dedicated tab in the Google Sheets Master Database stores submission records:

| Column Header | Data Type | Description & Example |
| :--- | :--- | :--- |
| `Submission_ID` | String | Unique reference ID (e.g., `QP-2026-8A31`) |
| `Submitted_At` | ISO Datetime | Timestamp of submission (`2026-08-11 22:30`) |
| `Teacher_Name` | String | Name of the submitting faculty member |
| `Grade` | String / Int | Grade level (`9`) |
| `Subject` | String | Subject name (`Physics`) |
| `Exam_ID` | String | Standardized exam identifier (`EXAM_MID_TERM_2026`) |
| `Submission_Type` | String | `Direct Text` or `File Upload` |
| `File_URL` | String (URL) | Google Drive shareable link to attachment / PDF |
| `Text_Content` | Long Text | Raw text content (if typed directly in-app) |
| `Status` | String | Workflow status (`Pending`, `Approved`, `Revision Needed`) |
| `Admin_Feedback` | String | Review comments from Principal / Coordinator |

### Tier 2: Cloud File Storage (Google Drive Integration)
* **Storage Location:** A dedicated Google Drive folder (e.g., `PSCC_Question_Papers_2026/`).
* **Automated Upload:** File uploads (`.pdf`, `.docx`, `.png`, etc.) and generated PDF exports from direct text are pushed to Google Drive via the Google Drive API (`PyDrive2`).
* **Public Access Link:** The public/viewable URL generated by Drive is recorded in the `File_URL` column of `Question_Papers_Log`.

---

## 4. Admin & Academic Review Panel

An integrated review screen allows the Principal or Academic Coordinator to manage submissions:
1. **Filter Submissions:** View submissions filtered by Grade, Subject, Exam Term, or Status (`Pending`, `Approved`, `Revision Needed`).
2. **Document Viewer:** Embedded PDF viewer and direct text reader for reviewing submitted papers.
3. **Approval Action:** Buttons to **Approve Paper** or **Request Revision** with custom feedback notes sent to the teacher.

---

## 5. Technical Stack Summary

* **UI Framework:** Streamlit (`st.selectbox`, `st.radio`, `st.text_area`, `st.file_uploader`, `st.download_button`).
* **Database:** Google Sheets (`gspread` client).
* **Cloud Storage:** Google Drive API (`PyDrive2` / `google-api-python-client`).
* **PDF Generation:** `reportlab` / `fpdf2` for converting in-app typed text into printable PDFs.
